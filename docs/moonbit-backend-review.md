The design has one architectural blocker and several acceptance mismatches. References below use the installed serde 1.0.229, serde_json 1.0.151, and MoonBit core. No files changed.

1. **P0 — `Json` cannot preserve the promised wire behavior** ([design L46](docs/moonbit-backend.md:46)). `Object(Map[String, Json])` discards duplicate keys: serde rejects duplicate named fields but maps generally overwrite them. Flatten serialization can itself produce duplicate keys. Sorting during parsing also destroys input order needed by flatten dispatch. Preserve ordered key/value pairs through decoding and serialization; converting through `serde_json::Value` is not equivalent to `from_str::<T>`.

2. **P1 — Flatten consumption is wrong** (L128–131). `Option<T>` suppresses decoding errors, **not mutations**: a plain flattened struct claims recognized fields before decoding their values, including on failure. Conversely, a struct containing flatten calls `deserialize_map`, borrows the outer buffer, and builds its own buffer. Flattened maps borrow remaining entries without consuming them; declaration order matters. Outer `deny_unknown_fields` checks leftovers, so a catch-all map does not necessarily satisfy it. A flattened plain struct’s own denial cannot see keys filtered out by `FlatStructAccess`. See [serde’s flatten implementation](~/.cargo/registry/src/index.crates.io-*/serde-1.0.229/src/private/de.rs:3184) and `serde_derive/src/de/struct_.rs`.

3. **P1 — Core trait composition changes the wire format** (L38–42). MoonBit’s built-in `Option` encodes `Some(x)` as `[x]`; `Int64`/`UInt64` encode as strings; integer decoding can truncate fractions. Generated codecs must recursively use serde-compatible helpers, including inside collections. Implementing traits only for named generated types is insufficient. See [core codecs](~/.moon/lib/core/json/from_json.mbt:54) and `builtin/json.mbt:241–329`.

4. **P1 — Missing/default rules need separation** (L121–127). Ordinary object-field `Option` accepts absence; typify’s **Required Option** deliberately rejects it through `deserialize_with` ([rust/serde_attr.mbt](rust/serde_attr.mbt:68)). Missing sequence elements do not receive that implicit `None`. Defaults apply to absence, not explicit null, and Rust `Default` is not a MoonBit “zero value”: `flatten-default.rs:21` constructs nonempty values; Rust array defaults contain N elements, whereas MoonBit `FixedArray::default()` is empty. Nested-option collapse is typify’s code-generation rule, not general Rust type semantics.

5. **P1 — Enum/struct acceptance is underspecified** (L133–142). Ordinary non-flatten structs and external struct-variant payloads accept positional arrays. Internal tagging also accepts sequences beginning with the tag; adjacent tagging accepts `[tag, content]`. Adjacent `Newtype(Option<T>)` can omit content. Internal **unit variants ignore extra fields even with `deny_unknown_fields`**. External unit variants serialize only as `"V"` although both documented inputs deserialize. Untagged struct variants lack the ordinary struct’s sequence visitor. See `serde_derive/src/de/{struct_,enum_internally,enum_adjacently}.rs` and [serde visitors](~/.cargo/registry/src/index.crates.io-*/serde-1.0.229/src/private/de.rs:838).

6. **P1 — Map keys require deserializer-context fidelity** (L88). Direct numeric `MapKey` uses JSON-number syntax, rejecting `"01"`, `"+1"`, and escaped digits such as `"\u0031"`; integer keys reject `"1.0"`. Decoding already-unescaped strings cannot reproduce this. Flatten/untagged buffering instead presents string `Content`, which can reject numeric keys accepted directly. Enum/newtype keys must follow their actual serde implementation, not merely `FromStr`. See [serde_json `MapKey`](https://raw.githubusercontent.com/serde-rs/json/master/src/de.rs).

7. **P1 — Number rules need explicit cases** (L46–62, L75–81). Integer destinations reject `1.0`, `1e0`, and `-0`; out-of-range integer tokens may become floats. Float destinations accept integer tokens, reject numeric strings, and have overflow/rounding behavior affected by `float_roundtrip`; nonfinite serialized values become null. Pin features. Moreover, [builtin `Json::Eq`](~/.moon/lib/core/builtin/json.mbt:35) ignores `repr`, conflating distinct large integers and integer/float classifications—unsafe for enum/deny-value constraints.

8. **P1 — Type mappings lose invariants** (L75–95). `FixedArray[T]` carries no N, so public construction permits wrong-length output; plain integers likewise permit invalid `i8`/NonZero values. Enum/newtype map keys need transitive `Hash` and `Eq`, absent from the proposed item rules. Erasing `Box` is reasonable, but recursive generation needs cycle tracking; `tests/upstream/impl/vega.out:11453` exercises it. Falling back to `Json` for unknown native types cannot claim parity. **Byte, Int16, and UInt16 exist**; verify required imports/codec support rather than rejecting those mappings.

9. **P2 — Identifier rewriting needs collision allocation** (L149–156). `is` and `is_` both become `is_`; generated helper names and builtin type names also collide. Validate the whole identifier and use scope-aware disambiguation.

10. **P2 — Tests can conceal failures** (L160–170). Re-serialization cannot identify overlapping untagged variants; emit explicit variant identities. Test raw text, duplicates, key permutations, invalid inputs, constructed values, recursion limits, and all targets. Tuple/array shortages produce visitor `invalid length`; excess elements commonly produce serde_json `trailing characters`, so length-only tests miss diagnostics. Canonicalization hides escaping/order differences; exact-text parity also contradicts the HashMap exception. Current core stringify defaults to unescaped `/` and serde-compatible control escaping; preserve that with byte-level tests. Rust key sorting needs the comparator in `collections/compare.mbt`, not default MoonBit string ordering.
